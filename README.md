# PS AI Agent — Автономная система для Siemens Plant Simulation 2404

**Версия:** ТЗ v1.0  
**Статус:** Рабочий прототип

## 📋 Описание

Полностью локальная автономная система, преобразующая текстовое описание производственной линии в готовую модель `.spp` в среде Siemens Plant Simulation 2404 без участия человека после инициации запроса.

## 🎯 Возможности

- **Автоматический парсинг** текстовых описаний на русском и английском языках
- **Генерация SimTalk кода** с учётом всех ограничений Plant Simulation 2404
- **Создание моделей** через COM-интерфейс
- **Валидация** созданных моделей
- **Самотестирование** API
- **Режим Dry-run** без подключения к Plant Simulation
- **Локальная LLM** (qwen2.5-coder:7b через Ollama)
- **Fallback-парсер** при недоступности LLM

## 🚀 Быстрый старт

### 1. Установка зависимостей

```bash
# Python зависимости
cd backend
pip install -r requirements.txt

# Node.js зависимости (для фронтенда)
cd ..
npm install
```

### 2. Установка Ollama и модели

```bash

```

### 3. Запуск Plant Simulation 2404

Откройте Siemens Plant Simulation 2404 (должен быть запущен).

### 4. Запуск системы

**Вариант A: Веб-интерфейс (рекомендуется)**
```bash

# Запуск бэкенда
```

**Вариант B: CLI**
```bash

python plant_agent_full.py --selftest
```

**Вариант C: Автоматический запуск**

## 📖 Использование

### Пример 1: Базовая линия

**Ввод:**
```
Линия: источник заготовок с интервалом 3 минуты, станция обработки 20 секунд, 
накопитель на 10 мест, сход
```

**Результат:**
- Создаются 4 объекта: Source, Station, Buffer, Drain
- Устанавливаются параметры: interval=180, procTime=20, capacity=10
- Объекты соединяются коннекторами
- Модель сохраняется в `model.spp`

### Пример 2: Множественные станции

**Ввод:**
```
Источник каждые 60 секунд, две станции по 15 секунд, буфер 5, выход
```

**Результат:**
- Source → Station_1 → Station_2 → Buffer → Drain
- Все параметры настроены согласно описанию

## 🔧 API Rules (Plant Simulation 2404)

Согласно ТЗ, система использует **только подтверждённые рабочие методы**:

| ✅ Работает | ❌ Не работает |
|------------|----------------|
| `createObject(f, x, y)` | `derive(root)` |
| `Connector.connect(obj1, obj2)` | `obj1.succ := obj2` |
| `Station`, `Buffer`, `Source`, `Drain` | `SingleProc`, `Entity` |
| `setName("Name")` | `.name := "Name"` |
| `.Models.Model` | `root` |

## 📊 Спецификация (JSON)

Система генерирует JSON-спецификацию формата:

```json
{
  "objects": [
    {
      "name": "SRC_1",
      "class": "Source",
      "x": 100,
      "y": 100,
      "params": {"interval": 180}
    },
    {
      "name": "ST_1",
      "class": "Station",
      "x": 220,
      "y": 100,
      "params": {"procTime": 20}
    }
  ],
  "connections": [
    ["SRC_1", "ST_1"]
  ]
}
```

## 🧪 Тестирование

### Selftest

Проверяет работоспособность API:
```bash
python plant_agent_full.py --selftest
```

Тестирует:
- Подключение к Plant Simulation
- `createObject()` метод
- `Connector.connect()` метод
- Неработоспособность устаревших методов

### Dry-run

Генерирует JSON и SimTalk без выполнения:
```bash
python plant_agent_full.py --dry-run "Источник 120 сек, станция 30, выход"
```

Выводит:
- JSON-спецификацию
- Сгенерированный SimTalk код

### End-to-end

Полный цикл с сохранением модели:
```bash
python plant_agent_full.py "Линия: источник 180 сек, станция 20, буфер 10, сход" test_model.spp
```

## ⚙️ Режимы работы

### Полный режим
- Plant Simulation запущен
- Все операции выполняются в реальном PS
- Модель сохраняется в `.spp`

### Демо-режим
- Plant Simulation не запущен
- Симулирует выполнение
- Показывает какие команды будут отправлены

### Без Ollama
- Используется fallback regex-парсер
- Остальные агенты работают нормально

## 🔒 Безопасность

- **Полностью локально** — никаких облачных API
- Весь трафик LLM через `localhost:11434`
- Не требует прав администратора (кроме регистрации COM)

## 🐛 Отказоустойчивость

- **Автоперезапуск COM** при обнаружении zombie-процессов PS
- **Healing attempts** — до 3 попыток автоисправления кода
- **Fallback-парсер** при недоступности LLM
- **Демо-режим** при отсутствии Plant Simulation

## 📝 Логирование

Все операции записываются в `agent_log.txt`:
- Запросы к LLM
- Сгенерированный SimTalk код
- Ошибки COM
- Результаты валидации

## 📚 Сценарии использования (User Stories)

**US-1:** Инженер вводит текст → система создаёт модель за <15 секунд  
**US-2:** Работа без Ollama через regex-парсер  
**US-3:** Автообнаружение и перезапуск zombie-процессов PS

- ✅ Все объекты в кадре `.Models.Model`
- ✅ Количество коннекторов = N-1 (где N — количество объектов)

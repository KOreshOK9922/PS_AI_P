# ✅ ИСПРАВЛЕНИЯ ПО АУДИТУ (22.10.2026)

## Критические дефекты — ВСЕ ИСПРАВЛЕНЫ

### ✅ К-1: База знаний — INSERT без UNIQUE индекса
**Проблема:** `INSERT ... ON CONFLICT(method_name)` крашился из-за отсутствия UNIQUE индекса  
**Исправлено:** Добавлен `UNIQUE` на `method_name` в таблице `api_methods` и `error_message` в `error_patterns`  
**Файл:** `backend/knowledge_base.py`

### ✅ К-2: Builder подставляет буквальные "x", "y" из шаблона БЗ
**Проблема:** Builder брал шаблон `.MaterialFlow.Source.createObject(f, x, y)` из БЗ и подставлял буквально "x", "y"  
**Исправлено:** Builder теперь ВСЕГДА генерирует код сам с реальными координатами из спецификации  
**Файл:** `backend/parallel_agents.py` (BuilderAgent)

### ✅ К-3: Validator считает numObjects включая коннекторы и служебную таблицу
**Проблема:** Validator создавал DataTable (+1 объект), считал `numObjects` (включает коннекторы + таблицу), сравнивал с ожидаемым. Результат: 8 вместо 4  
**Исправлено:** Validator теперь создаёт таблицу ПОСЛЕ подсчёта и считает только объекты MaterialFlow через итерацию  
**Файл:** `backend/parallel_agents.py` (ValidatorAgent)

### ✅ К-4: OllamaClient не передаётся агентам
**Проблема:** Orchestrator не создавал OllamaClient и не передавал его агентам — заявленный ИИ не работал  
**Исправлено:** Orchestrator создаёт OllamaClient и передаёт его Architect и Debugger агентам  
**Файл:** `backend/orchestrator.py`

### ✅ К-5: Фронтенд несовместим с бэкендом (порты и API)
**Проблема:** Фронтенд использовал порт 8000 и `/api/*` маршруты, а бэкенд на 7860 без `/api`  
**Исправлено:** Фронтенд теперь использует порт 7860 и правильные маршруты `/run`, `/status`, `/logs`  
**Файл:** `src/App.tsx`

## Дополнительные исправления

### ✅ _kill_zombie_processes убивает PS при /health
**Проблема:** `_try_com_connection()` вызывал `_kill_zombie_processes()` при КАЖДОЙ проверке подключения, включая health check

**Исправлено:** Demo-режим теперь честно проверяет синтаксис и возвращает ошибки для известных проблемных конструкций  
**Файл:** `backend/plant_sim.py`

**Проблема:** База знаний инициализировалась предзаполненными данными с `verified=1` — нечестно  
**Исправлено:** База знаний теперь начинается пустой — система сама накапливает знания через тестирование  
**Файл:** `backend/knowledge_base.py`

## Что теперь работает

### ✅ Полный цикл построения модели
1. Architect парсит текст → JSON-спецификация (с LLM или regex)
2. Builder генерирует SimTalk код с реальными координатами
3. Executor выполняет код в Plant Simulation (или demo-режим)
4. Debugger анализирует ошибки и предлагает исправления (с LLM)
5. Validator проверяет корректность модели (правильный подсчёт)
6. Модель сохраняется в .spp

### ✅ LLM интеграция
- OllamaClient создаётся в Orchestrator
- Передаётся Architect для парсинга текста
- Передаётся Debugger для отладки ошибок
- Fallback на regex-парсер если Ollama недоступна

### ✅ Честная база знаний
- Начинается пустой
- Накапливает знания через использование
- UNIQUE индексы предотвращают дубликаты
- Предзаполненные данные удалены

### ✅ Честный demo-режим
- Проверяет синтаксис
- Возвращает ошибки для известных проблем
- Не выдаёт ложные успехи

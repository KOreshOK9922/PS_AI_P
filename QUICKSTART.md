# 🚀 Быстрый старт

## Установка за 5 минут

### 1. Клонирование и установка

```bash
# Клонировать репозиторий
git clone <repository-url>
cd multi-agent-system

# Установить Python зависимости
cd backend
pip install -r requirements.txt

# Установить Node.js зависимости
cd ..
npm install
```

### 2. Установка Ollama

```bash
# Скачать Ollama: https://ollama.com/download
# Установить и загрузить модель:
ollama pull qwen2.5-coder:7b
```

### 3. Сборка и запуск

```bash
# Собрать frontend
npm run build

# Запустить backend
cd backend
python main.py
```

### 4. Открыть в браузере

Откройте: **http://localhost:8000**

## Первый запуск

1. Введите требование:
   ```
   Создай REST API для управления пользователями
   ```

2. Нажмите **"▶ Запустить"**

3. Наблюдайте за работой 7 агентов:
   - 🎯 Оркестратор координирует
   - 📊 Аналитик формализует требования
   - 🏛️ Архитектор проектирует
   - 💻 Разработчик пишет код
   - 🧪 QA тестирует
   - 🔍 Ревьюер проверяет
   - 🚀 DevOps упаковывает

4. Просматривайте артефакты во вкладке **"📦 Артефакты"**

## Примеры требований

### REST API
```
Создай REST API для управления пользователями с регистрацией, 
авторизацией и CRUD операциями. Используй FastAPI и PostgreSQL.
```

### CLI утилита
```
Создай CLI утилиту для конвертации файлов из CSV в JSON 
с валидацией и обработкой ошибок.
```

### React компонент
```
Создай React компонент для отображения графика с данными 
из API, с фильтрацией и сортировкой.
```

### Микросервис
```
Создай микросервис для обработки платежей с интеграцией 
Stripe API и webhook уведомлениями.
```

## Что происходит под капотом

### Фаза 1: Анализ (10-30 сек)
📊 **Product Analyst** анализирует требование и создаёт `requirements.md` с:
- User Stories
- Функциональными требованиями
- Edge cases
- Критериями приёмки

### Фаза 2: Архитектура (20-60 сек)
🏛️ **System Architect** проектирует архитектуру:
- Выбор стека технологий
- Структура проекта
- API контракты
- Схема данных

### Фаза 3: Реализация (30-120 сек)
💻 **Lead Engineer** пишет код:
- Следование SOLID/DRY/KISS
- Типизация и документация
- Модульность
- Обработка ошибок

### Фаза 4: Тестирование (20-60 сек)
🧪 **QA Engineer** тестирует:
- Unit тесты
- Integration тесты
- Покрытие кода
- Валидация требований

### Фаза 5: Ревью (15-45 сек)
🔍 **Code Reviewer** проверяет:
- Качество кода
- Безопасность (OWASP)
- Соответствие архитектуре
- Читаемость

### Фаза 6: Упаковка (10-30 сек)
🚀 **DevOps Engineer** создаёт:
- Dockerfile
- docker-compose.yml
- CI/CD конфигурацию
- .env файлы

### Цикл обратной связи
Если QA или Reviewer находят проблемы:
- Код возвращается Разработчику
- Максимум 3 итерации исправлений
- Автоматическая эскалация Оркестратору

## Решение проблем

### Ollama не отвечает
```bash
# Проверьте что Ollama запущена
ollama list

# Перезапустите службу
# Windows: Перезапустите службу Ollama
# Linux: sudo systemctl restart ollama
```

### Порт занят
```bash
# Найдите процесс
netstat -ano | findstr :8000  # Windows
lsof -i :8000                 # Linux/macOS

# Убейте процесс
taskkill /F /PID <PID>
```

### Медленная генерация
- Используйте более мощную модель: `qwen2.5-coder:14b`
- Увеличьте RAM
- Используйте GPU (опционально)

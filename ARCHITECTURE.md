# 🏗️ Архитектура мультиагентной системы

## Обзор

Мультиагентная система для автономной генерации высококачественного программного кода на базе локальных LLM.

## Компоненты

**Технологии:**
- React 18
- TypeScript
- Tailwind CSS
- Vite

**Функции:**
- Ввод требований
- Мониторинг агентов в реальном времени
- Просмотр логов
- Просмотр артефактов

### 2. Backend (Python + FastAPI)

**Технологии:**
- Python 3.10+
- FastAPI
- asyncio
- httpx

**Функции:**
- REST API
- Управление задачами
- Оркестрация агентов
- Хранение состояния

### 3. LLM Client (Ollama)

**Технологии:**
- Ollama
- qwen2.5-coder:7b/14b/32b

**Функции:**
- Локальная генерация кода
- Анализ требований
- Ревью кода

## Архитектура агентов

### 1. 🎯 Orchestrator (Оркестратор)

**Роль:** Управление жизненным циклом задачи

**Ответственность:**
- Декомпозиция задачи
- Маршрутизация между агентами
- Контроль итераций (макс. 3)
- Принятие финальных решений

**Вход:** Требование пользователя  
**Выход:** Финальный отчёт

**Код:**
```python
class Orchestrator:
    async def run(self) -> dict:
        # 1. Анализ требований
        requirements = await self.analyst.analyze(requirement)
        
        # 2. Проектирование архитектуры
        architecture = await self.architect.design(requirements)
        
        # 3-6. Цикл реализации и проверки
        for iteration in range(max_iterations):
            code = await self.engineer.implement(...)
            tests = await self.qa.test(code, requirements)
            review = await self.reviewer.review(code, architecture)
            
            if tests.passed and review.approved:
                break
        
        # 7. Упаковка
        docker = await self.devops.package(code, ...)
        
        return {"success": True, "artifacts": {...}}
```

### 2. 📊 Product Analyst (Продуктовый аналитик)

**Роль:** Формализация требований

**Ответственность:**
- Анализ требования пользователя
- Создание User Stories
- Определение edge-кейсов
- Формулирование критериев приёмки

**Вход:** Текстовое требование  
**Выход:** `requirements.md`

**Промпт:**
```
Ты - продуктовый аналитик. Формализуй требования пользователя.
Создай документ requirements.md с:
- Обзором проекта
- User Stories
- Функциональными требованиями
- Нефункциональными требованиями
- Edge Cases
- Критериями приёмки
```

### 3. 🏛️ System Architect (Системный архитектор)

**Роль:** Проектирование архитектуры

**Ответственность:**
- Выбор технологического стека
- Проектирование структуры
- Определение API контрактов
- Схема данных

**Вход:** `requirements.md`  
**Выход:** `architecture.md`

**Промпт:**
```
Ты - системный архитектор. Спроектируй архитектуру решения.
Создай документ architecture.md с:
- Технологическим стеком
- Структурой проекта
- Компонентами
- API контрактами
- Схемой данных
- Паттернами проектирования
```

### 4. 💻 Lead Engineer (Ведущий разработчик)

**Роль:** Реализация кода

**Ответственность:**
- Написание кода по спецификациям
- Следование SOLID/DRY/KISS
- Типизация и документирование
- Базовые unit-тесты

**Вход:** `requirements.md`, `architecture.md`, feedback от ревьюера  
**Выход:** Исходный код (JSON с файлами)

**Промпт:**
```
Ты - ведущий разработчик. Реализуй код по спецификациям.
Требования к коду:
- SOLID, DRY, KISS
- Типизация
- Документация
- Модульность
- Обработка ошибок

Верни JSON с файлами:
{
  "files": [{"path": "...", "content": "..."}],
  "main_file": "...",
  "description": "..."
}
```

### 5. 🧪 QA Engineer (QA инженер)

**Роль:** Тестирование кода

**Ответственность:**
- Написание тестов (TDD)
- Unit, integration, e2e тесты
- Отчёт о покрытии
- Валидация требований

**Вход:** Код, `requirements.md`  
**Выход:** Тесты + отчёт (JSON)

**Промпт:**
```
Ты - QA инженер. Протестируй код и напиши тесты.
Верни JSON:
{
  "passed": true/false,
  "tests": [...],
  "coverage": 85,
  "test_files": [...],
  "failures": [...]
}
```

### 6. 🔍 Code Reviewer (Ревьюер кода)

**Роль:** Проверка качества кода

**Ответственность:**
- Статический анализ
- Security audit (OWASP Top-10)
- Проверка линтеров
- Оценка читаемости

**Вход:** Код, `architecture.md`  
**Выход:** Отчёт о ревью (JSON)

**Промпт:**
```
Ты - ревьюер кода и security аудитор. Проверь код на качество.
Проверь:
- Соответствие архитектуре
- SOLID, DRY, KISS
- Обработка ошибок
- Безопасность (OWASP)
- Читаемость

Верни JSON:
{
  "approved": true/false,
  "score": 85,
  "issues": [...],
  "summary": "..."
}
```

### 7. 🚀 DevOps Engineer (DevOps инженер)

**Роль:** Упаковка приложения

**Ответственность:**
- Создание Dockerfile
- docker-compose.yml
- CI/CD конфигурация
- .env файлы

**Вход:** Код, `requirements.md`, `architecture.md`  
**Выход:** Docker + CI/CD конфигурация (JSON)

**Промпт:**
```
Ты - DevOps инженер. Создай конфигурацию для упаковки.
Создай:
- Dockerfile
- docker-compose.yml
- GitHub Actions CI/CD
- .env.example

Верни JSON с содержимым файлов.
```

## Workflow

### Последовательность выполнения

```
1. Инициация
   └─> Orchestrator получает требование

2. Анализ требований
   └─> Product Analyst → requirements.md

3. Проектирование
   └─> System Architect → architecture.md

4. Реализация (цикл)
   ├─> Lead Engineer → код
   ├─> QA Engineer → тесты
   └─> Code Reviewer → ревью
   
   Если тесты не пройдены или ревью не одобрено:
   └─> Возврат к Lead Engineer с feedback (макс. 3 итерации)

5. Упаковка
   └─> DevOps Engineer → Docker + CI/CD

6. Завершение
   └─> Orchestrator → финальный отчёт
```

### Цикл обратной связи

```
Итерация 1:
  Engineer → QA → Reviewer
  ↓ (если ошибки)
Итерация 2:
  Engineer (с feedback) → QA → Reviewer
  ↓ (если ошибки)
Итерация 3:
  Engineer (с feedback) → QA → Reviewer
  ↓ (если ошибки)
Эскалация Orchestrator'у
```

## Безопасность

### Изоляция

- Агенты работают в изолированной директории
- Нет доступа к чувствительным данным
- Код выполняется в sandbox (опционально Docker)

### Локальная LLM

- Данные не покидают машину
- Нет зависимости от облачных API
- Полный контроль над моделями

## Масштабирование

### Горизонтальное масштабирование

- Несколько Orchestrator'ов
- Распределённая очередь задач
- Load balancer для API

### Вертикальное масштабирование

- Более мощная LLM (32b, 70b)
- GPU acceleration
- Распараллеливание агентов

## Мониторинг

### Метрики

- Время выполнения задачи
- Количество итераций
- Покрытие тестами
- Оценка ревью
- Использование токенов

### Логи

- Все действия агентов
- Ошибки и предупреждения
- Артефакты и их изменения

## Расширение

### Добавление новых агентов

1. Создать класс агента в `agents.py`
2. Определить роль и промпт
3. Добавить в Orchestrator
4. Обновить frontend

### Интеграция внешних инструментов

- Git для версионирования
- Docker для изоляции
- CI/CD системы
- Системы мониторинга

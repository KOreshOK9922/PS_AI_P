**Версия:** 2.0  
**Статус:** Рабочий прототип с параллельными агентами и базой знаний

## 🎯 Что нового в v2.0

### Параллельные агенты
- **7 специализированных агентов** работают асинхронно
- **Supervisor** координирует работу всех агентов
- Каждый агент имеет свою зону ответственности
- Агенты работают параллельно через `asyncio`

### База знаний
- **SQLite база** для накопления опыта
- Автоматическое запоминание рабочих методов
- Поиск решений при ошибках
- Статистика успешности методов

### Мульти-интерфейс к Plant Simulation
- **COM/DCOM** — классический метод
- **REST API** — веб-интерфейс (экспериментальный)
- **Python Interface** — встроенный Python в PS 2404
- **SimTalk файлы** — выполнение скриптов
- **Автоматическое определение** доступного метода

### Автономное исследование
- Параллельное тестирование методов API
- Автоматическое накопление знаний
- Поиск альтернативных решений при ошибках

## 🤖 Параллельные агенты

### 1. Supervisor Agent 👑
**Роль:** Координирует работу всех агентов
- Управляет конвейером обработки
- Распределяет задачи между агентами
- Мониторит статусы и ошибки
- Принимает решения при сбоях

### 2. Architect Agent 🏗️
**Роль:** Парсит текстовое описание в JSON-спецификацию
- LLM парсинг через Ollama
- Fallback regex-парсер
- Валидация спецификации
- Извлечение параметров

### 3. Builder Agent 🔨
**Роль:** Генерирует SimTalk код из JSON
- Генерация `createObject()` вызовов
- Генерация `Connector.connect()` соединений
- Установка параметров
- Использование базы знаний

### 4. Executor Agent ⚡
**Роль:** Выполняет код через COM/REST/Files
- Мульти-интерфейс к Plant Simulation
- Обработка ошибок
- Повторные попытки (до 3 раз)
- Запись результатов в БЗ

### 5. Debugger Agent 🐛
**Роль:** Анализирует ошибки и ищет решения
- Поиск похожих ошибок в БЗ
- LLM-отладка через Ollama
- Генерация альтернативных решений
- Запись новых решений в БЗ

### 6. Researcher Agent 🔬
**Роль:** Исследует API, тестирует методы
- Параллельное тестирование методов
- Интроспекция атрибутов
- Экспериментальные подходы
- Накопление знаний

### 7. Validator Agent ✅
**Роль:** Проверяет корректность модели
- Подсчёт созданных объектов
- Проверка соединений
- Валидация параметров
- Сравнение со спецификацией

## 🧠 База знаний

### Структура базы данных

```sql
-- Методы API с статистикой
CREATE TABLE api_methods (
    method_name TEXT,
    code_template TEXT,
    success_rate REAL,
    attempts INTEGER,
    successes INTEGER,
    notes TEXT
);

-- Шаблоны ошибок и решения
CREATE TABLE error_patterns (
    error_message TEXT,
    solution TEXT,
    frequency INTEGER,
    last_seen TEXT
);

-- Рабочие решения
CREATE TABLE working_solutions (
    task_description TEXT,
    solution_code TEXT,
    success_count INTEGER
);

-- Классы объектов
CREATE TABLE object_classes (
    class_name TEXT,
    create_method TEXT,
    required_params TEXT,
    verified INTEGER
);
```

### Как работает накопление знаний

1. **При успехе:** метод записывается с увеличением счётчика
2. **При ошибке:** ошибка ищется в БЗ, если найдена — применяется решение
3. **При исследовании:** новые методы тестируются и записываются
4. **При отладке:** найденные решения сохраняются для будущего использования

### Пример использования

```python
from backend.knowledge_base import kb

# Записать попытку
kb.record_attempt("Connector.connect", success=True)

# Записать ошибку
kb.record_error("Unknown identifier 'connect'", solution="Используйте Connector.connect")

# Получить лучший метод
best = kb.get_best_method("connect")
print(f"Лучший метод: {best['name']} (успешность: {best['success_rate']})")

# Найти похожую ошибку
solution = kb.find_similar_error("Unknown identifier")
if solution:
    print(f"Решение: {solution['solution']}")
```

### Поддерживаемые методы

| Метод | Статус | Описание |
|-------|--------|----------|
| **COM/DCOM** | ✅ Работает | Классический COM-интерфейс |
| **REST API** | ⚠️ Экспериментальный | Веб-интерфейс PS 2404 |
| **Python Interface** | 🔬 Исследуется | Встроенный Python в PS 2404 |
| **SimTalk файлы** | ✅ Работает | Выполнение скриптов из файлов |
| **Demo** | ✅ Всегда доступен | Симуляция без PS |

### Python Interface (новое в PS 2404)

Plant Simulation 2404 имеет **встроенный Python объект**:

```simtalk
var py : object
py := .Python.createObject(f, 100, 100)
py.sourceCode := "print('Hello from PS!')"
py.execute()
```

**Преимущества:**
- Прямой доступ к объектам PS
- Использование Python библиотек
- Интеграция с AI/ML
- Чтение/запись DataTable

## 🔬 Исследование API

### Параллельное исследование

Система может автоматически исследовать API Plant Simulation:

```python
# Через веб-интерфейс
# Нажмите "🔬 Исследовать"

# Или через API
POST /research
{
  "task": "full"  # full, connections, classes
}
```

### Что исследуется

1. **Методы создания объектов**
   - `createObject()` vs `derive()`
   - Различные классы (Source, Station, Buffer, Drain)

2. **Методы соединений**
   - `Connector.connect()`
   - `succ :=`
   - `connect()`

3. **Параметры**
   - `interval`, `procTime`, `capacity`
   - Чтение/запись

4. **Экспериментальные методы**
   - Координаты объектов
   - Атрибуты через интроспекцию

### Результаты сохраняются

Все результаты автоматически записываются в базу знаний:
- Успешные методы → увеличивают `success_rate`
- Неудачные методы → записываются с ошибкой
- Новые находки → добавляются в БЗ

## 🐛 Обработка ошибок

### Автоматическая отладка

При ошибке выполнения:

1. **Debugger Agent** анализирует ошибку
2. **Поиск в БЗ** похожих ошибок
3. **LLM-отладка** через Ollama (если доступна)
4. **Генерация альтернатив** кода
5. **Повторная попытка** с исправленным кодом
6. **Запись решения** в БЗ для будущего использования

### Пример

```
[ERROR] Executor: Unknown identifier 'connect'
[INFO] Debugger: Поиск решения в базе знаний...
[INFO] Debugger: Найдено решение: Используйте Connector.connect()
[INFO] Executor: Повторная попытка с исправленным кодом...
[SUCCESS] Executor: Код выполнен успешно
[INFO] Debugger: Решение записано в базу знаний
```

## 🎯 Сценарии использования

### US-1: Базовое моделирование
**Как** инженер, **я хочу** ввести текст и получить готовую модель, **чтобы** ускорить прототипирование.

**Решение:** Параллельные агенты обрабатывают запрос за 5-15 секунд.

### US-2: Работа без LLM
**Как** пользователь на изолированном контуре, **я хочу** чтобы система работала без Ollama, **чтобы** гарантировать базовую функциональность.

**Решение:** Fallback regex-парсер активируется автоматически.

### US-3: Накопление знаний
**Как** система, **я хочу** запоминать рабочие методы, **чтобы** улучшаться со временем.

**Решение:** База знаний SQLite накапливает опыт и решения.

### US-4: Автономное исследование
**Как** разработчик, **я хочу** чтобы система сама исследовала API, **чтобы** находить новые методы.

**Решение:** Researcher Agent тестирует методы параллельно и записывает результаты.

## 🔒 Безопасность

- **Полностью локально** — никаких облачных API
- Весь трафик LLM через `localhost:11434`
- База знаний хранится локально в SQLite
- Не требует прав администратора

# PS AI Agent — Автономная система ИИ-агентов для Plant Simulation 2404

## Что это?

Автономная система, которая:
1. Принимает текстовое описание производственной линии
2. Автоматически строит модель в Siemens Plant Simulation 2404
3. Настраивает параметры объектов
4. Соединяет объекты
5. Сохраняет готовую модель

**Всё локально.** Без облачных API. Без участия человека после запуска.

## Быстрый старт

### 1. Установите зависимости

```bash
# Python
cd backend
pip install -r requirements.txt

# Node.js (для фронтенда)
cd ..
npm install
```

### 2. Установите Ollama и модель

```bash
# Установите Ollama: https://ollama.com
ollama pull qwen2.5-coder:7b
```

### 3. Запустите Plant Simulation 2404

Откройте Siemens Plant Simulation 2404.

### 4. Запустите систему

```bash
# Терминал 1: Бэкенд
cd backend
python main.py

# Терминал 2: Фронтенд (для разработки)
npm run dev

# ИЛИ: Соберите и обслуживайте через бэкенд
npm run build
python backend/main.py
# Откройте http://localhost:8000
```

### 5. Используйте

Откройте http://localhost:8000 и введите описание:

```
Источник заготовок с интервалом 3 минуты, станция обработки 20 секунд, 
накопитель на 10 мест, сход
```

Нажмите **"Запустить агента"**.

## Как это работает

### Фаза 1: Архитектор (LLM)
- Принимает текстовое описание
- Ollama (qwen2.5-coder:7b) парсит в JSON-спецификацию
- Если LLM недоступна — fallback regex-парсер

### Фаза 2: Строитель
- Генерирует SimTalk код из спецификации
- Создаёт объекты: Source, Station, Buffer, Drain
- Генерирует команды установки параметров
- Генерирует попытки соединений (несколько методов)

### Фаза 3: Исполнитель
- Выполняет код через COM-интерфейс
- `ExecuteSimTalk()` для каждого блока
- Логирует успех/ошибку каждого метода

### Фаза 4: Исследователь (если ошибки)
- Автоматически пробует все известные методы соединений
- Интроспекция атрибутов объектов
- Тестирует экспериментальные подходы
- Записывает рабочие и нерабочие методы

### Фаза 5: Валидатор
- Сохраняет модель в .spp
- Проверяет целостность

## Подтверждённые факты API (PS 2404)

### ✅ Работает:
```python
.MaterialFlow.Source.derive(root)      # Создание объектов
.MaterialFlow.Station.derive(root)      # Station (не SingleProc!)
pa.setName("SRC_1")                     # Переименование
root.SRC_1.interval := 120              # Параметры
root.ST_1.procTime := 15
root.BUF_1.capacity := 5
root.SRC_1.deleteObject                 # Удаление
```

### ❌ Не работает:
```python
root.SRC_1.succ := root.ST_1            # succ — read-only!
.MaterialFlow.SingleProc.derive(root)   # Нет такого класса
pa.name := "..."                        # name — read-only!
.create(root)                           # Только derive()
```

## Авто-исследование

Система автоматически исследует API, если стандартные методы не работают:

1. Создаёт тестовые объекты
2. Пробует 20+ методов соединений
3. Интроспекция атрибутов через `putAttributeNamesIntoTable()`
4. Экспериментальные подходы (xPos/yPos, Connector варианты)
5. Записывает результаты в базу знаний

## Режимы работы

### Полный режим (Plant Simulation запущен)
- Все операции выполняются в реальном PS
- Модель сохраняется в .spp

### Демо-режим (PS не запущен)
- Симулирует выполнение
- Показывает какие команды будут отправлены
- Исследователь работает с демо-данными

### Без Ollama
- Используется fallback regex-парсер
- Остальные агенты работают нормально

## Решение проблемы соединений

**Главная проблема PS 2404:** нельзя программно создать соединения через COM.

Система автоматически ищет решение:
1. Пробует все 15+ известных методов
2. Интроспекция атрибутов
3. Экспериментальные подходы
4. Если найден рабочий — применяет его
